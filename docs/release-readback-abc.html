2026-05-26 · 分支 readback-abc · 3 commits · 11 V 验证脚本全绿

一句话

之前 agent 把 HTML 推上去就完事了； 现在它可以读回用户填的内容、阻塞等用户的新动作、看每个字段是什么时候被谁改的。

三件事

Phase AURL 对称：读回路径 = 页面路径

之前

curl .../pages/<key>
# HTML

curl .../state/pages/<key>
# state — 路径不对称

现在

curl .../pages/<key>
# HTML

curl .../pages/<key>/state
# state — 路径对称（旧路径仍然可用）

Skill 里加了三个 cookbook：读单页 / 跨页汇总 / debug 排错。 默认 UA 是 livehtml-agent-readback/1，access log 一眼能区分 agent 读回和人浏览。

Phase B不再轮询，agent 可以挂着等

LIVEHTML=http://localhost:39191   # 换成你的部署地址
curl "$LIVEHTML/pages/<key>/state?wait=30&since=<etag>"

# 用户一改就立刻返回：
{"status":"changed","etag":"<bootId>:12","version":12,"state":{"task-1":true,...}}

# 超时无变化：
{"status":"not_modified","etag":"<bootId>:11","version":11}

# 服务器重启过：
{"status":"reset","etag":"<newBootId>:0","version":0,"state":{...}}

不用 SSE 不用 WebSocket，普通 curl 就能阻塞最多 60 秒。 since 用 bootId:version 不透明 etag，服务重启自动 reset，agent 知道要重新基准化。

Phase C可选元数据：谁、什么时候改的

默认 GET（不破老 client）

curl .../pages/<key>/state
{
  "task-1": true,
  "note": "ok"
}

加 ?meta=1

curl .../pages/<key>/state?meta=1
{
  "version": 2,
  "fields": {
    "task-1": { "v": true,
                "ts": "2026-05-26T08:42:31Z",
                "by": "User-7421" },
    "note":   { "v": "ok",
                "ts": "2026-05-26T08:42:35Z",
                "by": "http" }
  }
}

磁盘格式自动升级到 envelope，旧文件（无 version 字段）仍然能读。 浏览器同步行为零变化，sync.js 一行没动。
